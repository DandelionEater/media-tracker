# Seenary 0.1.7 Beta

Tag: `v0.1.7-beta`

## Highlights

This update expands Seenary into an Anime and Manga library while continuing to polish everyday navigation, details, privacy, synchronization, and data safety.

## New and improved

- Home and My List now share one responsive **Library Lens** instead of separate page-specific switches. A single control combines the Anime/Manga context with Personal, Discover, and My List destinations, persists both choices, migrates the previous saved tabs, and follows the media type of titles opened from search or relations.
- The navbar's My List shortcut now yields while the Library Lens is visible, avoiding duplicate My List controls, and returns automatically after the Lens scrolls out of view or the user opens a page without it.
- A global scroll-to-top button now appears after meaningful vertical scrolling across Home, Discover, search results, My List, media details, and Settings. It follows the active page surface, stays clear of the center quick-actions pill, and returns smoothly to the top without reacting to horizontal shelves or nested notification and modal scrolling.
- The Manga Personal lens now has its own overview totals and Continue Reading shelf, with volume and chapter progress kept separate from Anime statistics. Manga Discover mirrors Anime's browsing experience with a trending carousel plus Publishing Now, New & Noteworthy, Popular, and Highly Rated shelves and expandable paginated views.
- Manga Personal now mirrors the full Anime dashboard with a reading spotlight, Manga-native account overview, status totals, Continue Reading, Plan to Read, favorite-based Manga recommendations, Recently Updated, empty states, density-aware cards, carousel behavior, and configurable section ordering. Its layout is persisted independently as `mangaPersonalLayoutOrder`, so arranging Manga never rearranges Anime Home.
- Anime and Manga Discover overviews now arrive in one combined AniList GraphQL request and share one privacy-aware cache. Switching the Library Lens reuses the already-loaded half locally instead of doubling network requests, while opening a specific shelf still loads its media-qualified pages only when requested.
- Combined search still exposes both media types, but now places the active Library Lens first. This keeps cross-media discovery available without making Manga results dominate an Anime search—or forcing Manga users to scroll through Anime adaptations first.
- Anime detail pills are now color-coded for quicker scanning. Upcoming titles use red, currently airing titles use green, and finished titles use blue. Format, season, and episode information use their own separate violet, amber, and silver treatments so they do not compete with airing status colors.
- Anime formats now preserve familiar capitalization, including `TV` and `TV SHORT`.
- Anime details now request AniList's extra-large cover artwork. Covers remain compact on the details page and open no larger than their natural size in the artwork inspector, preserving more detail for deliberate zooming. Banners also open at their natural size instead of being stretched to fill the inspector.
- Artwork inspector controls now occupy and cover the quick-actions pill's bottom-screen position while inspection is active instead of following the artwork's height. Short banners no longer leave the control pill floating across the middle of the enlarged image.
- Artwork inspector wheel zoom now anchors to the cursor like CAD and map applications in both directions: the point beneath the pointer remains in place while zooming in or out, without the shrinking pan boundary pulling the image toward center. Reaching the fitted 100% view recenters it cleanly. Double-click zoom uses the clicked point as its anchor, while the dedicated zoom buttons intentionally remain center-based.
- Successful automatic syncs now create both a toast and a notification naming the Anime or Manga title and every linked third-party service that received it. Partial and failed automatic syncs also provide appropriate warning or error feedback instead of completing silently.
- Re-enabling the 18+ filter now immediately removes adult titles from already-loaded search, trending, Discover, and expanded shelf content. Opening a previously cached adult title shows a privacy-safe hidden state, and saved adult titles remain in My List with their title, artwork, notes, and recommendation metadata redacted while the filter is active.
- Searches with no matches now show a clear empty-results message with suggestions instead of silently returning to the home screen. Searches whose matches are all hidden by the 18+ filter explain that separately, and every search state is positioned safely below the navigation bar.
- Pressing Enter while the search field is focused now dismisses the search results and returns to the home content without clearing the query. Focusing the field again restores the retained search, while Delete continues to clear it explicitly.
- Navbar actions clicked with the mouse no longer retain focus and consume the next Enter press. Keyboard tab navigation remains unchanged, while Enter reliably returns to the global search shortcut after mouse navigation.
- Typing while search is unfocused now preserves the first typed character. Type-to-search focuses the field without selecting and replacing that initial input, while explicit Enter or mouse focus can still select an existing query for convenient replacement.
- Returning focus to a retained search now reruns the query with the current 18+ preference instead of restoring stale results. This makes switching the filter in either direction consistent without requiring the user to edit the query manually.
- Search now requests Anime and Manga together in one AniList media query, then separates the response into clearly labelled Anime and Manga sections with independent counts and empty states. Manga results already include type-safe chapter, volume, format, score, and artwork metadata while their details and list-tracking paths are built out.
- Manga search results now open a context-sensitive details page built on the same visual shell as Anime details. Manga pages show known chapters and volumes, publishing status and dates, publication age, creators and staff, characters, relations, recommendations, official links, artwork, scores, genres, and tags while omitting anime-only runtime, airing, studio, trailer, streaming, and episode controls. Cross-media relations retain both media type and ID so Anime adaptations and their source Manga can navigate safely in either direction.
- My List now has an Anime/Manga switch positioned below the page introduction and above its search controls. Manga receives Reading, Plan to Read, Completed, Paused, and Dropped presentation across List, Grid, and Board views, with independent remembered view, sorting, open-section, filter, and section-order preferences.
- Manga tracking now supports the complete local create, read, update, and delete workflow from Manga details and My List. Users can track chapters and volumes separately, score and favorite titles, save notes and dates, manage rereads, increment chapter progress quickly, mark publications complete, and remove entries without placing Manga records into Anime storage.
- Missing Manga chapter and volume totals now use publishing-aware language instead of a blanket `Unknown`: ongoing publications show `Ongoing`, future titles show `TBA`, hiatus titles show `Unconfirmed`, and finished titles with incomplete AniList metadata show `Not listed`.
- Manga details now request AniList's version 2 publication status, allowing titles classified as `HIATUS` or `CANCELLED` on AniList to appear correctly instead of being flattened into the legacy `RELEASING` state.
- Manga progress consistently presents Volumes before Chapters in both the list editor and details summary, reflecting the publication hierarchy while continuing to track chapters cumulatively across the series. The editor scrollbar is moved into the modal's outer right padding so it no longer overlaps progress controls.
- Desktop layout configuration now stores Manga's My List section order separately as `mangaMyListSectionOrder`, alongside the existing Anime `myListSectionOrder`, so editing one tab never overwrites the other and both remain visible in `seenary-config.json`.
- My List now remembers whether Anime or Manga was last open and restores that sub-page, together with its own view and layout preferences, the next time the page is opened.
- Manual sync now sends queued Anime and Manga changes to every linked service in one run, including AniList and MyAnimeList when both are connected. Manga mappings preserve reading status, chapters, volumes, scores, notes, dates, rereads, updates, and deletions through each provider's native fields and endpoints.
- Automatic sync now uses the same media-aware Anime/Manga pipeline as manual sync. Manga additions, edits, progress updates, and deletions schedule background delivery to every linked provider, followed by the existing descriptive toast and notification when the run completes.
- Update from third party now pulls Anime and Manga together from either AniList or MyAnimeList. Manga imports retain reading status, chapter and volume progress, scores, notes, dates, and rereads, use AniList IDs as Seenary's canonical media identity, and record media-aware pull history without sending the imported state straight back to its source provider.
- Sync Activity now includes a dedicated Pulled tab for durable third-party update records. It separates pull history from outbound Completed and Failed activity, preserves per-title field changes, records a summary even when nothing changed, and keeps partial mapping conflicts or fatal pull errors readable after the toast disappears.
- Sync Activity titles now follow the user's English, Romaji, native, or AniList-preferred title setting across queued, pushed, completed, failed, and pulled records. Existing history resolves through cached media metadata, while provider-only titles remain available as a safe fallback when no canonical media record exists.
- Sync queues, history, retry activity, and completion records are now media-aware, so Anime and Manga with overlapping numeric IDs cannot overwrite or mislabel one another. Existing Anime sync records migrate transactionally, while Manga saved before this update is enrolled in its first manual sync automatically.
- Local backups are now media-aware schema version 2 files. They preserve Anime and Manga metadata, list entries, chapter and volume progress, media-aware external IDs, pending changes and deletions, sync history, settings, and the auto-sync preference across browser-local and development Electron storage. Existing version 1 Anime-only backups remain importable and restore additively without removing Manga already on the device.
- Settings now provides separate Clear Anime list, Clear Manga list, and Clear all media actions. Each action names its exact scope, warns that synchronized removals may reach linked services, and requires a second explicit confirmation before changing data.
- Users can now permanently delete their Seenary account from the Danger zone. Deletion requires opening a second confirmation and typing the exact username, then removes Anime and Manga list data, sync queues and history, linked-service credentials, sessions, browser-local state, and saved desktop layouts without deleting the user’s AniList or MyAnimeList account or remote lists.

## Reliability and fixes

- The Library Lens now remains beneath the fixed navigation bar while page content scrolls, preventing its controls from covering the navbar.
- Account deletion is now a transactional, media-aware cleanup. The older internal deletion path omitted Manga and several account-owned records; it now clears every user-owned database row before removing the profile.
- Automatic sync feedback is emitted only after the background sync finishes, so notifications reflect the actual result rather than merely confirming that a change was queued.
- Clearing a score or note now sends MAL explicit reset values instead of omitting those fields and leaving the previous remote values untouched. Manga entries falsely marked as synced under the earlier payload behavior are identified and requeued once with the corrected values.
- MyAnimeList Manga pulls now resolve their canonical AniList identity without sending a conflicting empty AniList ID, fixing Manga entries that were silently skipped despite having an exact MAL mapping. An anomalous AniList 404 receives one delayed retry, while genuinely unmapped remote entries are reported by title as a partial update instead of being hidden behind a successful zero-change message.
- MyAnimeList Anime pull conflicts now name the skipped title and are written with their MAL ID and reason to the development log. Titles represented as separate MAL entries but bundled into one AniList record are described as one-to-one mapping conflicts instead of being silently collapsed and overwriting one another's status.
- Public MyAnimeList imports now request the list owner's status and progress fields instead of the authenticated viewer's unrelated `my_list_status` field. This prevents valid public libraries from being reduced to an empty picker, and a zero-match result now explains whether the public list was empty or its entries could not be mapped safely.
- Text and PDF imports now require an explicit Anime or Manga interpretation mode. Each mode searches only its matching AniList media type, presents episode or chapter-aware previews, uses collision-safe media-qualified selections, and saves entries into the correct Anime or Manga library; Anime remains the compatibility default.
- Packaged and web-local imports now retain episode duration metadata instead of discarding it while caching the list. This fixes severe Time Watched undercounting in `0.1.6-beta`; the development SQLite and packaged local-storage paths now use the same progress-by-duration calculation and data coverage.
- Creating a new Seenary profile through AniList or linking AniList to an existing profile now imports both Anime and Manga immediately. The authenticated desktop and packaged/web flows share the same media-aware collection loaders, and Manga-only accounts are no longer skipped by the browser-local import guard.
- Importing by a public AniList account name now previews and selectively imports both Anime and Manga. The picker separates media and status clearly, shows Manga chapter and volume progress, and uses media-qualified selections so an Anime and Manga sharing the same AniList number cannot affect one another.
- Import from MyAnimeList is now a genuine public username import instead of requiring a linked account and duplicating account sync. Seenary reads public MAL Anime and Manga lists with its application identity, maps them to canonical AniList records, and presents the same media-aware selective picker; linking remains reserved for private-list access and ongoing synchronization.
- Adult-content metadata is now retained in anime details and local list caches. Existing list entries with older cached metadata are classified automatically so the 18+ filter can hide them without deleting personal progress.
- Manga storage is introduced through additive SQLite tables and version-tolerant browser-local state fields, preserving existing Anime libraries during the beta migration. Manga now participates in the same media-aware manual and automatic sync queues without entering Anime-specific storage.
